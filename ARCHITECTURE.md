# Kadr — архитектура скриншотера

> Рабочее название **Kadr**, поменяем. Платформа: Windows 11 (22H2+), Windows 10 22H2 — по возможности.
> Статус: M0 готов; M1 частично готов: выделение, экспорт PNG, режимы захвата и живой конфиг. Текущее состояние и остаток работ — в `STATUS.md`, результаты M0 — в §18.
>
> **Решено:**
> - пишем на Rust;
> - программа только для личного использования;
> - редактируем только «на месте», поверх экрана;
> - вместо полной истории храним 10 последних несохранённых скринов;
> - дизайн: направление из awesome-claude-design (editorial), проверка через ui-ux-pro-max,
>   полировка через taste-skill (§17).

## 1. Цели

**Что делаем:** резидентный скриншотер в духе Lightshot. Нажал PrtSc — экран мгновенно «замёрз», выделил область,
порисовал, подписал, размыл лишнее, затем скопировал или сохранил. Плюс то, чего Lightshot не умеет:

- снимки поверх *любых* окон, включая диспетчер задач;
- **аккуратное и при этом необратимое размытие** чувствительных данных (§9);
- **«Недавние»:** до 10 последних несохранённых скринов переживают закрытие, выход из программы и даже сбой (§10);
- правка фигур после рисования, закрепление снимка поверх экрана, OCR.

**Бюджеты производительности** (меряем с первого дня, см. §14):

| Метрика | Цель |
|---|---|
| Хоткей → замороженный экран на всех мониторах | ≤ 40 мс p95 (2 монитора, 4K) |
| Отклик оверлея на мышь (включая живое размытие) | ≤ 1 кадр (vsync) |
| Ctrl+C → картинка в буфере обмена | ≤ 30 мс (4K) |
| Сохранение PNG 4K | ≤ 150 мс, в фоне; оверлей закрывается сразу |
| Простой: CPU / RAM | 0 % / ≤ 25 МБ private |
| Размер exe | ≤ 10 МБ |

**Принципы**

1. **Сначала кадр, потом интерфейс.** Пиксели снимаем раньше, чем показываем хоть одно окно.
2. **На горячем пути ничего не создаём.** GPU-устройство, шрифты, иконки, окна оверлея готовы заранее.
3. **Пиксели живут на GPU до экспорта.** Оверлей рисует прямо из GPU-текстуры захвата.
4. **UI-поток никого не ждёт:** ни диска, ни UI Automation, ни кодеков.
5. **Один рендерер для экрана и экспорта.** Что видишь, то и сохраняется, включая размытие.
6. **Скрин не теряется.** Кадр и правки автосохраняются в «Недавние» в фоне.
7. **Модель документа — чистый Rust без Win32.** Её можно тестировать и переиспользовать.
8. **Меряем, а не предполагаем.** Таймингам горячего пути — спаны и встроенный perf-HUD.

## 2. Почему Lightshot «слепнет» над диспетчером задач — и как решаем

Захват пикселей тут **не проблема**: DXGI Desktop Duplication отдаёт скомпонованную картинку рабочего стола,
и диспетчер задач в ней есть. Мешают два других барьера.

1. **UIPI (изоляция ввода).** Диспетчер задач запущен с повышенными правами (High integrity). Если в фокусе
   окно с более высоким уровнем целостности, обычный процесс (Medium) не получает нажатие PrtSc ни через
   low-level хук, ни через `RegisterHotKey`: до скриншотера оно просто не доходит. Это подтвердил замер M0 (§18.2).
2. **Z-order bands.** В режиме «Поверх остальных окон» диспетчер задач живёт в отдельной полосе z-порядка
   (`ZBID_SYSTEM_TOOLS`), а она выше обычной. `HWND_TOPMOST` сортирует окна только *внутри* обычной полосы,
   поэтому оверлей окажется под диспетчером.

**Решение — режим `uiAccess`.** Процесс с `uiAccess="true"` в манифесте, подписанный и установленный в
`Program Files`, получает:

- ввод со всех уровней целостности: хоткей срабатывает над любым окном;
- окна в полосе `ZBID_UIACCESS`, выше диспетчера задач, меню «Пуск» и панели задач;
- доступ UI Automation к элевированным окнам, что нужно для умного выделения (§6.3).

При этом процесс остаётся на уровне Medium, **не администратор**.

**Как это устроено у нас (программа для себя):**

- **Скрипт `installer/install.ps1`** нужно запускать от администратора. Он делает всё сам, без Windows SDK:
  1. Создаёт самоподписанный сертификат подписи кода (`New-SelfSignedCertificate -Type CodeSigningCert`,
     закрытый ключ неэкспортируемый) в хранилище текущего пользователя.
  2. Добавляет публичную часть сертификата в доверенные корневые (`LocalMachine\Root`) и доверенных издателей.
  3. Подписывает exe (`Set-AuthenticodeSignature`).
  4. Копирует программу в `C:\Program Files\Kadr\`.
  5. Прописывает автозапуск (ключ `Run`).
- **Повторный запуск скрипта = обновление.** Сертификат он переиспользует.
- **Важно про сертификат:** всё, что подписано этим ключом, твоя машина считает доверенным. Ключ лежит только у тебя
  и не экспортируется. Это нормальная практика для личных инструментов.
- **Debug-сборки — без `uiAccess`** (манифест выбирает `build.rs` по фиче `uiaccess`). Они запускаются прямо из
  `target/`, просто без суперсилы над элевированными окнами.
- **Запуск `uiAccess`-программы только через `ShellExecute`** (автозапуск через `Run` так и работает). У
  `CreateProcess` будет `ERROR_ELEVATION_REQUIRED`.

**Почему не «запуск от администратора».** По имеющимся данным это не меняет полосу z-порядка. Вдобавок файлы
и буфер обмена обрабатывались бы с правами админа, а drag-and-drop в обычные приложения сломался бы.
**Всё это проверяем руками в спайке M0** (§15).

**Чего не будет никогда (и это правильно):**

- **Защищённый рабочий стол** (UAC-запрос, Ctrl+Alt+Del, экран блокировки) пользовательскому процессу недоступен.
- **Окна с `WDA_EXCLUDEFROMCAPTURE`** (часть менеджеров паролей, DRM-видео) получаются чёрными.

## 3. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Язык | **Rust** (stable, MSVC) | Нет GC-пауз и рантайма, маленький exe, безопасность памяти в процессе с `uiAccess` |
| Win32/WinRT | `windows` (windows-rs, от Microsoft) | Полное покрытие API, включая WinRT (OCR, WGC) |
| Захват | DXGI Desktop Duplication → WGC → GDI | См. §5 |
| Рендер | Direct3D 11 + Direct2D 1.1 + DirectWrite + DirectComposition | Аппаратный 2D, эффекты (Gaussian blur, масштабирование), качественный текст, flip-модель с низкой задержкой |
| Иконки | SVG через `ID2D1SvgDocument` | Чёткие на любом DPI |
| Кодеки | `png` (fdeflate) для PNG, WIC для JPEG/WebP | Быстрый PNG без C-зависимостей |
| Конфиг | TOML (`serde`) | Читаемо, правится руками |
| «Недавние» | Папки на диске, шифрование DPAPI, **без БД** | 10 записей — база данных не нужна |
| ГСЧ для размытия | `getrandom` (системный криптостойкий ГСЧ) | Шум, который нельзя предсказать (§9) |
| Окно настроек | **Slint** (стиль fluent) в **отдельном процессе** | Не на горячем пути, своя петля событий |
| Логи и метрики | `tracing` + ротация файлов | Спаны горячего пути |
| Установка | PowerShell-скрипт + самоподписанный сертификат | Программа для себя, MSI не нужен |

## 4. Процессы и потоки

```
┌────────────────────── kadr.exe (резидентный, uiAccess) ──────────────────────┐
│                                                                              │
│  UI-поток (главный)                       Рабочие потоки                     │
│  ├─ скрытое message-окно                  ├─ pool: снимок окон, кодирование, │
│  │   WM_HOTKEY · трей · WM_RENDERFORMAT   │        запись файлов, размытие   │
│  ├─ захват кадра (синхронно, ~5–15 мс)    ├─ uia: COM MTA, запросы с         │
│  ├─ окна оверлея (по одному на монитор)   │       дедлайном, «последний      │
│  ├─ контроллер редактора + инструменты    │       побеждает»                 │
│  ├─ рендер Direct2D                       ├─ store: единственный писатель   │
│  └─ закреплённые снимки (pin)             │        «Недавних» (черновики)    │
│                                           └─ ipc: сервер named pipe          │
│        ▲  PostMessage(WM_APP+n) / каналы crossbeam  ▲                        │
└────────┼────────────────────────────────────────────┼────────────────────────┘
         │ named pipe \\.\pipe\kadr-<SID> (ACL: только текущий пользователь)
┌────────┴───────────────── kadr-ui.exe (по требованию) ───────────────────────┐
│  Окно настроек (Slint). Читает и пишет config.toml; ядру шлёт только         │
│  «тест хоткея» и «показать Недавние».                                        │
└──────────────────────────────────────────────────────────────────────────────┘
```

**Почему два процесса.**

- **Ядро остаётся крошечным** и не падает из-за окна настроек.
- **Нет конфликта петель сообщений:** у Slint своя, у ядра — своя.
- **Окно настроек не получает `uiAccess`,** которое ему не нужно.

Ядро следит за `config.toml` (`ReadDirectoryChangesW`) и применяет изменения на лету. Пока окна настроек нет
(до M3), конфиг правится руками через пункт трея «Открыть настройки».

**Единственный экземпляр:** именованный мьютекс `Local\Kadr-<SID>`. Второй запуск передаёт аргументы первому
через pipe и завершается. Pipe, а не `WM_COPYDATA`, потому что pipe не упирается в UIPI.

**Модель многопоточности редактора:** документ и инструменты живут только в UI-потоке, поэтому в модели нет ни
одного мьютекса. Воркеры получают неизменяемые снимки (`Arc<DocState>`, пиксели) и возвращают результат сообщением.

## 5. Горячий путь: хоткей → замороженный экран

```
t=0     WM_HOTKEY → скрытое окно (UI-поток). WM_HOTKEY даёт право на SetForegroundWindow
 │
 ├─[UI]     для каждого монитора: AcquireNextFrame → CopyResource в свою текстуру → ReleaseFrame
 ├─[pool]   параллельно: снимок окон (EnumWindows, DWMWA_EXTENDED_FRAME_BOUNDS, отсев cloaked)
 ├─[UI]     текстуры → ID2D1Bitmap1 без копирования; первый кадр рендерится в ещё скрытые (cloaked) оверлеи
 ├─[UI]     DWMWA_CLOAK=false + SetForegroundWindow   → экран «замёрз»
t≈20–40 мс
 └─[UI idle] копия кадра в staging-текстуру → Map → CPU-копия кадра
              ├─► store: создать черновик в «Недавних» (кодирование PNG + DPAPI в фоне)
              └─► размытие берёт исходные пиксели отсюда (§9)
```

**Приёмы, без которых 40 мс не получить:**

- **Окна оверлея создаются при старте** и прячутся через DWM-cloaking, а не `ShowWindow(SW_HIDE)`. Показ сводится к
  снятию маскировки, первый кадр отрисован заранее. Плюс `DWMWA_TRANSITIONS_FORCEDISABLED`, чтобы не было анимации.
- **Стили окна:** `WS_POPUP`, `WS_EX_TOOLWINDOW | WS_EX_TOPMOST | WS_EX_NOREDIRECTIONBITMAP`. Swap chain через
  DirectComposition, flip-discard, frame-latency waitable object.
- **D3D-устройство создаётся на адаптере, которому принадлежит выход.** На ноутбуках с двумя GPU иначе
  `DuplicateOutput` вернёт `DXGI_ERROR_UNSUPPORTED`.
- **Прогрев дубликатора.** Его создание стоит порядка 10–30 мс, а постоянное удержание может мешать играм.
  Стратегия выбирается по замерам в M0.

### 5.1 Бэкенды захвата

```rust
trait CaptureBackend {
    fn capture_all(&mut self, monitors: &[MonitorInfo]) -> Result<CapturedFrame>;
}

struct CapturedFrame {
    monitors: Vec<MonitorFrame>,      // текстура на GPU своего адаптера + rect в физ. пикселях + формат
    cursor: Option<CursorSnapshot>,   // форма и позиция — отдельным слоем документа
    windows: WindowSnapshot,          // заполняется параллельно (pool)
    taken_at: Instant,
}
```

| Бэкенд | Когда | Особенности |
|---|---|---|
| **DXGI Desktop Duplication** | по умолчанию | Самый быстрый, без рамки, отдаёт форму курсора. На `DXGI_ERROR_ACCESS_LOST` пересоздаём и повторяем один раз |
| **Windows.Graphics.Capture** | захват отдельного окна, фолбэк | Умеет снимать окно, *перекрытое другими* (M4). На Win11 рамку убирает `IsBorderRequired=false` |
| **GDI BitBlt + CAPTUREBLT** | RDP, VM, экзотические драйверы | Медленнее (~30–60 мс на 4K), зато работает везде |

### 5.2 Мониторы, DPI, HDR

- **DPI-осведомлённость процесса — PerMonitorV2.** Все координаты захвата и документа хранятся в **физических
  пикселях виртуального рабочего стола**. Тулбар, шрифты и маркеры масштабируются по DPI своего монитора.
- **Один оверлей на монитор.** Выделение хранится в глобальных координатах и может тянуться через мониторы.
- **Преобразование вида (view transform) «документ → экран».** Для живого захвата оно тождественное. Для скрина,
  восстановленного при другой раскладке мониторов, это сдвиг и масштаб (§10).
- **HDR.** `DuplicateOutput1` с FP16 → оверлей на scRGB swap chain. При экспорте — тонмаппинг в SDR с учётом SDR
  white level монитора, чтобы снимки не выходили «выцветшими».
- **`WM_DISPLAYCHANGE`, подключение и отключение мониторов, смена DPI** → пересобираем оверлеи, дубликаторы обновляем лениво.

## 6. Оверлей и выделение

### 6.1 Состояния (конечный автомат контроллера)

```
           хоткей                 отпустили мышь / клик по окну
 Idle ───────────────► Selecting ─────────────────────────────► Selected ◄──────┐
  ▲ │                    │ Esc                                    │  │          │
  │ │◄───────────────────┘                             выбрал     │  │ Esc из   │
  │ │                                                  инструмент │  │ инструм. │
  │ │     Ctrl+C / Enter / Ctrl+S / Esc / pin                     ▼  │          │
  │ └──────────────────────────────────────────── Annotating(tool) ──┴──────────┘
  │                                                   │ клик по фигуре ▲
  │  хоткей «Недавние»                                ▼                │
  └──────────► RecentPicker ──► Selected            EditingShape / EditingText
                (выбрал скрин)   (восстановленный)
```

### 6.2 Selecting

- Затемнение экрана ~40 %, крестик и **лупа**: увеличенные пиксели, координаты, цвет под курсором. По `C` копируется HEX.
- Подсветка окна или элемента под курсором; клик выбирает подсвеченное, перетаскивание — произвольную область.
- `Space` при перетаскивании двигает рамку. После выделения: маркеры, стрелки ±1 px, `Shift`+стрелки ±10 px.
- Шорткаты привязаны к VK-кодам, поэтому работают и в русской раскладке (`B` = `И`).

### 6.3 Умное выделение

1. **`WindowSnapshot`** снимается в момент захвата: видимые не-cloaked окна в z-порядке, рамки DWM без тени,
   дочерние окна на 1–2 уровня. Поиск под курсором мгновенный, в памяти.
2. **UI Automation** (M4) уточняет элемент: кнопку, панель, ячейку. Запрос идёт в `uia`-поток с дедлайном
   ~50 мс. Если UIA не успел, остаётся рамка окна.

## 7. Модель документа (`kadr-doc`, без Win32)

```rust
struct DocState {                      // неизменяемый снимок; clone дешёвый
    crop: RectI,                       // выделение, физ. пиксели виртуального экрана
    shapes: Vec<Arc<Shape>>,           // порядок = z-order
}

struct Shape { id: ShapeId, kind: ShapeKind, style: Style }

enum ShapeKind {
    Arrow { from: Pt, to: Pt, head: ArrowHead },
    Line { from: Pt, to: Pt },
    Rect { rect: Rect, radius: f32 },
    Ellipse { rect: Rect },
    Pen { points: Vec<StrokePoint> },       // сглаживание при рендере; давление пера из WM_POINTER
    Highlighter { points: Vec<StrokePoint> },
    Text { pos: Pt, text: String, font: FontSpec, wrap_width: Option<f32>, backdrop: Backdrop },
    Counter { pos: Pt, n: u32 },            // шаги 1, 2, 3… с автонумерацией
    Blur(BlurShape),                        // §9
    Redact { rect: Rect },                  // сплошная заливка — запасной вариант, не основной
    Spotlight { rect: Rect },               // затемнить всё, кроме
    Cursor { pos: Pt, image: ImageRef },    // курсор с момента захвата — можно сдвинуть или удалить
}

struct BlurShape {
    area: BlurArea,          // Rect { rect, radius } | Ellipse { rect } | Brush { points, width } | AllExcept { rect }
    strength: BlurStrength,  // Soft | Normal | Strong
    feather: f32,            // мягкость края, px
    seed: u64,               // для шума; из криптостойкого ГСЧ при создании, в экспорт не попадает
}

struct Style { stroke: Color, fill: Option<Color>, width: f32, opacity: f32, shadow: bool }
```

- **Координаты фигур абсолютные.** Поэтому рамку выделения можно менять *после* рисования, а экспорт просто сдвигает всё на `-crop.origin`.
- **Undo/redo — стек снимков `DocState`.** Непрерывные действия (перетаскивание, рисование) — один шаг: снимок при нажатии, коммит при отпускании.
- **Команды** (`AddShape`, `UpdateShape`, `Delete`, `Reorder`, `SetCrop`) — единственный способ менять документ.
  Каждая команда заодно ставит отложенное автосохранение черновика (§10).
- **Размытие применяется к исходному кадру,** а не к фигурам под ним: результат предсказуем, кэшировать проще.

### 7.1 Инструменты

```rust
trait Tool {
    fn pointer_down(&mut self, cx: &mut ToolCx, e: &PointerEvent) -> Flow;
    fn pointer_move(&mut self, cx: &mut ToolCx, e: &PointerEvent) -> Flow;
    fn pointer_up(&mut self, cx: &mut ToolCx, e: &PointerEvent) -> Flow;
    fn key(&mut self, cx: &mut ToolCx, e: &KeyEvent) -> Flow;
    fn preview(&self) -> Option<Shape>;    // рисуется поверх, пока не закоммичено
    fn cursor(&self) -> CursorKind;
}
```

- **Каждый инструмент — маленький автомат,** документ он меняет только через `ToolCx::commit(Command)`.
- **Перо** берёт промежуточные точки (`GetPointerInfoHistory` / `GetMouseMovePointsEx`) для гладких линий.
- **Текст:** своё редактирование поверх DirectWrite (каретка, выделение, вставка), подложка или обводка для читаемости.
- **Колесо мыши** меняет толщину, размер шрифта или силу размытия; горячие клавиши выбирают инструменты.

## 8. Рендер (`kadr-render`)

Одна функция для экрана и экспорта:

```rust
fn render_document(gfx: &mut Gfx, doc: &DocState, base: &BaseImage, view: &ViewTransform, mode: RenderMode);
// RenderMode::Screen { chrome: &Chrome, dirty: Rect }  |  RenderMode::Export { scale: f32 }
```

**Слои и кэши:**

1. **Базовый кадр** — неизменная GPU-текстура.
2. **Размытия** — готовые битмапы, кэш по ключу `(shape id, area, strength, seed)`.
3. **Закоммиченные фигуры** — кэшируются в битмап слоя и пересобираются только при изменении документа.
4. **Фигура в процессе рисования** — рисуется вживую поверх кэша.
5. **Хром:** затемнение вне выделения, рамка, маркеры, подпись размера, тулбар, лупа.

Рендер идёт **только по событию**, без постоянного цикла. Движения мыши склеиваются до одного кадра на vsync,
`Present1` отдаёт dirty rects. При `DEVICE_REMOVED` GPU-контекст пересоздаётся из документа и CPU-копии кадра.

## 9. Размытие: красиво и необратимо

**Проблема.**

- **Обычное размытие по Гауссу частично обратимо.** Есть деконволюция, а главное — подбор: злоумышленник
  рендерит кандидатов тем же шрифтом, размывает так же и сравнивает. Против коротких цифр (номера карт, коды)
  подбор работает отлично.
- **Пикселизация тоже вскрывается** (известные инструменты вроде Depix).
- **Закрашивание надёжно, но выглядит грубо.**

**Наш подход: сначала уничтожить детали, потом красиво сгладить.**

```
 исходная область (+ запас по краям, чтобы край не темнел)
   │ 1. уменьшить блоками k×k с усреднением; сетка блоков со случайным сдвигом
   ▼
 крошечная картинка ──► 2. + случайный шум от криптостойкого ГСЧ
   │ 3. увеличить обратно плавно (бикубически)
   ▼
 4. размытие по Гауссу, σ ≈ k/2 ──► 5. мягкая маска: растушёвка / скругление / овал / след кисти
   ▼
 результат: ровное «матовое» размытие без квадратов; видно, что там был текст, но не какой
```

- **Шаг 1 физически стирает информацию** мельче блока: в пикселях её больше нет, восстанавливать нечего.
- **Шаг 2 ломает подбор.** Даже зная шрифт и алгоритм, точные значения повторить нельзя: шум случайный и в файл не попадает.
- **Шаги 3–5 отвечают только за красоту.** Никаких квадратов и резких краёв, размытие «вписано» в картинку.

**Сила** задаётся колесом мыши и считается от высоты строки текста в области:

| Сила | Размер блока k | Для чего |
|---|---|---|
| Мягкая | ≈ 1× высоты строки | Не секрет, а просто лишнее: ники, имена в чате, вкладки |
| **Обычная** (по умолчанию) | ≈ 1,5× | Почта, телефоны, адреса, суммы |
| Сильная | ≈ 2,5× + больше шума | Короткие цифровые секреты: коды 2FA, CVV, PIN, токены |

Высота строки оценивается по профилю яркости строк внутри области. Это дешёвая эвристика на CPU; если строки не
нашлись, берётся 16 px × масштаб монитора. В M4 оценка станет точной через OCR.

**Формы:** прямоугольник со скруглением, овал (лица), **кисть** (провёл по нужным строкам) и **«размыть всё,
кроме»** (фон размыт, выделенная часть резкая).

**Скорость.** Шаги 1–2 работают на CPU по уже готовой копии кадра (§5) над крошечной картинкой, это доли
миллисекунды. Шаги 3–5 — эффекты Direct2D на GPU. Поэтому размытие обновляется вживую, пока тянешь рамку.

**Гарантии:**

- **Всё, что уходит наружу, — плоская картинка:** PNG/JPEG, буфер обмена, перетаскивание, pin. Исходных пикселей
  под размытием в ней нет, слоёв и метаданных (заголовков окон, имени ПК) тоже.
- **Превью = экспорт.** Конвейер и seed одни и те же, поэтому уходит ровно то, что видишь.
- **Исключение — локальные черновики «Недавних»** (§10). Там оригинал хранится, чтобы можно было поправить размытие
  после восстановления. Они зашифрованы, а настройка `keep_original_under_blur = false` вжигает размытие и в черновик.
- **Для паролей и ключей лучше «Сильная» сила или «Закрасить».** Подсказка об этом появляется в тулбаре инструмента.

**Умное размытие (M4).** Кнопка находит через OCR почту, телефоны, номера карт, IBAN, IP-адреса и похожие на ключи
строки и предлагает размыть найденное разом. Это помощник, а не гарантия: финальное решение за тобой.

## 10. «Недавние»: 10 несохранённых скринов

**Идея:** каждая сессия захвата — это **черновик**. Он появляется сразу после захвата и тихо обновляется, пока ты
рисуешь. Если скрин так и не сохранили в файл, черновик остаётся в «Недавних», и его можно вернуть ровно в том виде,
в каком ты его оставил.

**Жизненный цикл черновика:**

```
 захват ──► open ──┬─ Ctrl+S (сохранён в файл) ──► удаляется: файл уже есть
                   │
                   └─ Esc / только Ctrl+C / закрыл pin / вышел из программы / сбой
                         ──► unsaved ──► лежит в «Недавних», при 11-м вытесняется самый старый
```

- **Черновик создаётся сразу после захвата, ещё до выделения.** Даже если нажал PrtSc и тут же Esc, кадр уже
  снят, и его можно вернуть. Например, если всплывашка исчезла, а ты промахнулся.
- **Автосохранение.**
  - Кадры всех мониторов пишутся один раз, в фоне.
  - Состояние документа (выделение, фигуры) пишется через ~300 мс после последней правки.
  - Запись атомарная (`tmp` + переименование). При сбое, перезагрузке или выходе теряются максимум доли секунды.
- **После сохранения:** если продолжил рисовать и закрыл без повторного сохранения, черновик снова становится `unsaved`.
- **Лимит:** `recent.max = 10` несохранённых. Опционально можно включить ещё и лимит по возрасту.

**Как вернуть скрин:**

- **Хоткей «Недавние»** (по умолчанию `Ctrl+Alt+PrintScreen`) или клик по иконке в трее. Поверх экрана
  открывается лента из 10 превью с временем; клик по превью — и сессия возобновляется на месте: замороженный
  кадр, выделение и все фигуры как были. История отмен после восстановления начинается заново.
- **Если раскладка мониторов изменилась,** кадр показывается на основном мониторе со сдвигом и масштабом через
  view transform (§5.2). Редактирование работает так же.
- **После сбоя:** при старте, если найден черновик в статусе `open`, всплывает уведомление
  «Скрин не был сохранён — восстановить?».

**Хранение:**

```
%LOCALAPPDATA%\Kadr\recent\<время>-<id>\
  meta.json          # время, статус, раскладка мониторов — без содержимого экрана, открытым текстом
  frame-0.png.enc    # кадры мониторов
  doc.json.enc       # выделение и фигуры
  thumb.jpg.enc      # превью для ленты
```

- **Шифрование:** `.enc` — это DPAPI (`CryptProtectData`, ключ привязан к твоей учётной записи Windows).
  Другие пользователи и копия диска прочитать скрины не смогут. Стоит единицы миллисекунд, делается в фоне.
- **Без базы данных.** При старте папка сканируется по `meta.json` за миллисекунды.
- **Объём:** кадр 2×4K в PNG занимает ~3–10 МБ, так что 10 черновиков — до ~100 МБ.
- **В трее** есть пункт «Очистить недавние», в настройках «Недавние» можно выключить совсем.

## 12. Конфиг (`kadr-store`)

Конфиг лежит в `%APPDATA%\Kadr\config.toml`, у него есть версия схемы, неизвестные поля не ломают загрузку:

```toml
[hotkeys]
region      = "PrintScreen"
fullscreen  = "Shift+PrintScreen"
window      = "Ctrl+PrintScreen"
last_region = "Ctrl+Shift+PrintScreen"
recent      = "Ctrl+Alt+PrintScreen"

[capture]
backend = "auto"          # auto | dxgi | wgc | gdi
include_cursor = false

[save]
folder   = "%USERPROFILE%\\Pictures\\Screenshots"
filename = "Screenshot_{date:%Y-%m-%d_%H-%M-%S}"
format   = "png"          # png | jpg | webp

[blur]
default_strength = "normal"   # soft | normal | strong
feather = 6

[recent]
enabled = true
max = 10
keep_original_under_blur = true
```

**Конфликт PrtSc.** В Win11 по умолчанию клавишу PrtSc забирает «Ножницы». Если `RegisterHotKey` вернул ошибку,
показываем уведомление с кнопкой отключить эту опцию (`HKCU\Control Panel\Keyboard\PrintScreenKeyForSnippingEnabled`)
и меняем её **только после подтверждения**.

kadr-app ─► kadr-editor ─► kadr-render ─► kadr-win
   │            └────────────┴──────────► kadr-doc ◄── kadr-store ◄── kadr-ui
   ├──────► kadr-capture ─► kadr-win
   └──────► kadr-export ─► kadr-render, kadr-doc

- `unsafe` и Win32 только в `kadr-win`, `kadr-capture` и `kadr-render`.

- `kadr-editor` не знает, как кадр был захвачен.

## 14. Надёжность, безопасность, тесты

**Надёжность:**

- **Логи** через `tracing` в `%LOCALAPPDATA%\Kadr\logs` с ротацией. Panic hook пишет лог и минидамп, черновик
  к этому моменту уже на диске.
- **Восстановление после сбоев:**
  - `ACCESS_LOST` → пересоздаём дубликатор;
  - `DEVICE_REMOVED` → пересоздаём GPU-контекст;
  - блокировка сессии → освобождаем дубликаторы;
  - сбой бэкенда захвата → откат на следующий бэкенд.

**Безопасность:**

- **Гигиена процесса с `uiAccess`:**
  - `SetDefaultDllDirectories`;
  - никаких плагинов;
  - pipe только для текущего пользователя;
  - лимиты на размеры при чтении черновиков.
- **Сеть:** никаких сетевых вызовов, всё локально.

**Тесты:**

| Что | Как |
|---|---|
| `kadr-doc` | Юнит- и property-тесты (`proptest`): геометрия, hit-test, инварианты undo, round-trip сериализации |
| `kadr-render` | Golden-тесты: `document.json` + `base.png` → офскрин-рендер на **WARP** (программный D3D, детерминирован) → сравнение с эталоном |
| **Необратимость размытия** | Автотест-атака: рендерим все коды `0000…9999` тем же шрифтом, размываем, пытаемся угадать исходник подбором. Тест падает, если для «Обычной» и «Сильной» силы угадывание лучше случайного |
| **«Недавние»** | Убиваем процесс посреди сессии → после перезапуска черновик восстанавливается с фигурами; 11-й черновик вытесняет самый старый; сохранённый в файл исчезает |
| Горячий путь | Спаны `hotkey → captured → first_present → visible`; `--perf-hud` выводит тайминги в углу оверлея, `--bench-hotpath N` печатает p50 и p95 |
| Ручная матрица | 1/2/3 монитора, DPI 100/150/200 % вперемешку, HDR, диспетчер задач «поверх всех», полноэкранная игра, RDP, ноутбук с двумя GPU |

## 17. Дизайн интерфейса

**Процесс** для каждого UI-этапа:

1. **Направление** — awesome-claude-design, семейство editorial.
2. **Компоненты и доступность** — проверка по ui-ux-pro-max. Его поисковый скрипт требует Python, которого на машине
   нет, поэтому правила берутся прямо из его справочников.
3. **Финальная полировка** — taste-skill по правилам app-screens: критика по скриншотам `kadr --snapshot`,
   не больше трёх кругов.

**Направление — editorial / Vercel, чистый грейскейл.** Первым вариантом был Linear с одним акцентом `#5e6ad2`.
От него отказались по двум причинам:

- **Индиго и фиолетовый под запретом в taste-skill.**
- **В скриншотере данные — это сам скрин.** Хром не должен повторять его цвета и спорить с ними, а фиолетовая
  рамка терялась бы на фиолетовом контенте.

**Токены** (`crates/kadr-app/src/theme.rs`):

| Роль | Значение | Проверка |
|---|---|---|
| Затемнение вне выделения | `#000` 50 % | — |
| Поверхность панелей | `#111111`, непрозрачная | Контраст текста не зависит от скрина |
| Рамка панелей | `#2e2e2e`, 1 px | — |
| Текст и цифры | `#ededed` | 16:1 на поверхности |
| Подписи и единицы | `#a1a1a1` | 7,3:1 (порог 4,5) |
| Рамка выделения | `#fff` 1,5 DIP + `#000` 60 % 1 DIP снаружи | Снаружи всегда затемнение: от 3,6:1 на белом скрине до 21:1 на чёрном |
| Шрифт | Segoe UI Variable Text, цифры табличные (`tnum`) | Одно семейство, цифры стоят разряд под разрядом |
| Размеры текста | 12 (подписи, цифры) · 13 (заголовок) · 24 (главная цифра) | Ничего мельче 12 |
| Радиусы и отступы | 4 / 8; сетка 4 · 8 · 12 · 16 | — |

**Правила:**

- **Цвет есть только у скрина.** Цвета аннотаций в M2 — это палитра пользователя, то есть данные, а не хром.
- **Панели непрозрачные, глубина только рамкой.** Без теней и градиентов.
- **У каждой панели одна главная цифра** — ответ на её вопрос.
- **Рамка лежит снаружи выделения** и не закрывает выбранные пиксели.
- **HUD не закрывает выделение:** встаёт в первый свободный угол.
- **Esc и правый клик отменяют всегда,** горячие клавиши подписаны прямо на панели.
- **В режиме высокой контрастности Windows** используются системные цвета.
- **Анимаций нет:** движение только как обратная связь (M1+).

**Проверка:** `kadr --snapshot out.png [--scale 1.5]` рисует сцену на синтетическом «худшем» фоне (белый, серые,
цвет бывшего акцента, чёрный, радуга) без реального экрана.

## 18. Спайк M0: результаты

Замер 2026-10-29 на машине разработки: RTX 4060 Ti, мониторы 2560×1440 и 1920×1080, оба 100 %. Release-сборка,
команда `kadr --bench 10 [--warm]`.

### 18.1 Задержка «хоткей → кадр на экране»

| Режим | p50 | p95 | Первый захват после запуска |
|---|---|---|---|
| on-demand | 23,5 мс | 33,0 мс | 25 мс |
| прогретый | **8,2 мс** | 13,6 мс | 14 мс |

- **Обе цифры в бюджете 40 мс.**
- **В on-demand почти всё время — ожидание первого кадра свежего дубликатора** (10–15 мс). Создание самого
  дубликатора стоит меньше 1 мс.
- **В прогретом режиме этапы такие:** захват 0,2 мс, рендер ~0,8, показ ~2,5, композиция DWM ~4–6.
- **Прогрев при старте обязателен.** Без него первый захват длился 55–65 мс: создание глифов, первый Present,
  композиция DWM, дубликатор.
- **Первый `SetForegroundWindow` стоит 20–30 мс.** Он вызывается после показа и картинку не задерживает.
- **Размер exe — 367 КБ.**

### 18.2 Находки

- **PrtSc на этой машине занят Lightshot.** Его `RegisterHotKey` срабатывает раньше нашего, и мы получаем
  «Hot key is already registered». На время теста есть запасной хоткей Ctrl+Shift+F12.
- **Без uiAccess над элевированным окном клавиша не доходит вообще.** Контрольный замер 2026-10-29: debug-сборка,
  Medium, Lightshot закрыт. С диспетчером задач в фокусе PrtSc не дал ни `WM_HOTKEY`, ни события LL-хука, в логе
  пусто. Над обычными окнами (claude.exe, explorer.exe) оба пути срабатывают. Значит, Lightshot «слепнет» над
  диспетчером уже на уровне хоткея, а не только из-за z-order.
- **Флаг `PrintScreenKeyForSnippingEnabled = 0`:** «Ножницы» PrtSc не забирают.
- **Код M0 — один крейт `kadr-app`.** Его модули повторяют будущие крейты (`capture`, `gpu`/`render`, `overlay`,
  `theme`, `app`). Разбиение на крейты по §13 — первый шаг M1.

### 18.3 Ручная проверка (её может сделать только человек)

1. **Подготовка.** Закрыть Lightshot (или отключить в нём PrtSc). Запустить `target\debug\kadr.exe`: у
   debug-сборки есть консоль с логом. Нажать PrtSc на обычном окне. Ожидается: замороженный экран, HUD с цифрами,
   выделение мышью (в том числе через границу мониторов), H скрывает панель, Esc или правый клик закрывают.
2. **Диспетчер задач без uiAccess.** Открыть диспетчер задач (Ctrl+Shift+Esc), включить «Поверх остальных окон»,
   кликнуть по нему и нажать PrtSc. В логе появится строка «PrtSc: WM_HOTKEY …, LL-хук …, передний план
   Taskmgr.exe». Смотрим две вещи:
   - пришёл ли WM_HOTKEY;
   - оказался ли оверлей над диспетчером.
3. **Диспетчер задач с uiAccess.** Собрать `cargo build --release --features uiaccess` и от администратора
   выполнить `powershell -ExecutionPolicy Bypass -File installer\install.ps1`. В HUD должно появиться
   «uiAccess». Повторить шаг 2.

Результат 2026-10-29:

| Что проверяем | Без uiAccess (debug-сборка) | С uiAccess (установлен через `install.ps1`) |
|---|---|---|
| PrtSc при диспетчере задач в фокусе | **не доходит**: нет ни `WM_HOTKEY`, ни события LL-хука | **доходит** |
| Скрин поверх диспетчера «поверх остальных окон» | не запускается | **работает**: оверлей над диспетчером |

**Вывод:** архитектурное решение §2 подтверждено — uiAccess обязателен, «просто хоткей» не спасает.

Особенность среды разработки: Claude Desktop — MSIX-пакет, и процессы, запущенные из него (инструменты агента,
вкладки терминала), пишут в `%LOCALAPPDATA%` через перенаправление в `Packages\Claude_…\LocalCache\Local`. Лог
установленного Kadr лежит в настоящем `%LOCALAPPDATA%\Kadr\logs` и открывается из трея: «Открыть лог».

Удаление: `installer\install.ps1 -Uninstall -RemoveCertificate`.
