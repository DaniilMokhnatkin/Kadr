# Выпуск Kadr

Версия берётся из `[workspace.package].version` в `Cargo.toml`. Тег должен быть
точно `vX.Y.Z` с той же версией. Тег `release` не является номером версии.
Первый установщик содержал Kadr 0.1.0, несмотря на название Ver1.0;
его файл и ссылки сохранены. Исправленный выпуск — 1.0.0.

## Следующая версия

1. Изменить версию в `Cargo.toml`, например на `1.0.1`; обновить `Cargo.lock` через Cargo.
2. Проверить изменения (`powershell -File tools/check.ps1`) и сделать коммит в `main`.
3. Создать новый тег на этом коммите и отправить его:

```powershell
git tag -a v1.0.1 -m "Kadr 1.0.1"
git push origin main
git push origin v1.0.1
```

Workflow `.github/workflows/release.yml` запускается на теги `v*`.
Он проверяет Clippy и тесты обновлятора, собирает Windows x64/uiAccess,
сверяет тег и версию Cargo, проверяет адрес обновлений и публикует
`Kadr-Setup.exe` и `SHA256SUMS.txt`. При несовпадении SHA-256 или размера
с данными GitHub релиз остаётся черновиком. Повторный запуск не перезаписывает
опубликованные версии: для исправления нужна новая версия и новый тег.
Теги на старые коммиты не передвигать.
Если выпуск остался черновиком из-за ошибки публикации, исправить workflow в `main`
и запустить `Release Kadr` вручную через Actions с исходным тегом в поле `tag`.
Он пересоберёт именно этот тег и продолжит работу с черновиком.

## Локальная сборка

```powershell
powershell -ExecutionPolicy Bypass -File installer/fetch-ocr.ps1
powershell -ExecutionPolicy Bypass -File installer/build-release.ps1 -Tag v1.0.0
```

Для последующих версий заменить тег на текущий. Скрипт только собирает:
он не запускает установщик и не добавляет сертификаты на компьютер.
Адрес GitHub задан в `.cargo/config.toml`; для форка переопределить `KADR_REPO`.

## Как обновляется установленная программа

Первый запрос — примерно через 45 секунд после запуска, затем раз в сутки;
пункт «Проверить обновления» в трее выполняет запрос сразу.
Программа читает `/releases/latest`, сравнивает числовой тег с собственной версией,
скачивает строго `Kadr-Setup.exe` из выбранного репозитория и проверяет SHA-256.
После нажатия «Обновить» установщик просит UAC, завершает старую копию,
заменяет программу, сохраняет настройки и запускает новую.

Тесты `update::tests` проверяют переход 0.1.0 → 1.0.0, отсутствие повторного
предложения 1.0.0 → 1.0.0, следующую версию 1.0.1 и отказ от неверных метаданных.
Отдельный тест с `--ignored` скачивает опубликованный установщик и проверяет
его тем же кодом, что используется при обновлении, но не запускает установку.
Физическая установка через UAC остаётся отдельной проверкой на Windows.
