# Kadr — состояние проекта, 29 октября 2026

M0 завершён. В M1 теперь есть «Недавние»: до 10 зашифрованных черновиков, фоновая запись, восстановление и превью. Доводка M1 ещё продолжается.

## Готово

- DXGI-захват двух мониторов, прогрев, оверлеи, PerMonitorV2 и замеры задержки.
- Выделение мышью, маркеры, клавиатура, привязка к окнам и лупа.
- После выбора целого окна/монитора можно заново обвести маленькую область внутри; вручную нарисованная рамка по-прежнему переносится за середину.
- Панель «Копировать / Сохранить / Сохранить как… / Закрыть».
- Ctrl+C / Enter, Ctrl+S, Ctrl+Shift+S, PNG и отложенный PNG в буфере.
- Разделение на восемь крейтов.
- Чтение `%APPDATA%\Kadr\config.toml`: хоткеи, прогрев, папка сохранения, уведомления.
- Горячее применение конфига по уведомлению файловой системы, без опроса диска в простое.
  Если открыто выделение, изменение откладывается до его закрытия. Ошибка файла сохраняет последние
  действующие настройки. Занятая новая комбинация вызывает откат к прежним настройкам.
- Меню трея с захватом области, монитора, повтором области и открытием настроек в Блокноте.
- Резервный Ctrl+Shift+F12; он не регистрируется отдельно, если уже назначен одному из режимов.
- Существующий установщик с uiAccess, подписью и автозапуском. Установленный exe обновляется отдельно.
- «Недавние»: кадры записываются один раз, выделение обновляется после 300 мс без правок и при закрытии.
  Esc и копирование сохраняют черновик; успешная запись PNG в файл удаляет только соответствующую ревизию.
- Открытие по Ctrl+Alt+PrintScreen, левому клику в трее или пункту «Недавние…».
  Превью с временем, восстановление одним нажатием, Tab/Space/Enter/Esc, очистка с подтверждением.
- После смены мониторов сохранённый рабочий стол вписывается в основной монитор с переносом выделения.
- DPAPI текущего пользователя защищает кадры, превью и документ; открытые временные PNG не создаются.

## Хоткеи по умолчанию

| Комбинация | Действие |
|---|---|
| PrintScreen | Выделить область |
| Shift+PrintScreen | Монитор под курсором сразу в буфер |
| Ctrl+PrintScreen | Видимая область активного окна сразу в буфер |
| Ctrl+Shift+PrintScreen | Последняя выделенная область сразу в буфер |
| Ctrl+Shift+F12 | Резервное выделение области |
| Ctrl+Alt+PrintScreen | Недавние несохранённые снимки |

Быстрые режимы не показывают оверлей и не забирают фокус. Снимок окна берётся с рабочего стола:
если окно перекрыто другим, перекрывающие пиксели попадут в снимок. «Чистый» захват окна через WGC — позже.
Последняя область хранится до выхода из приложения. При отключении монитора проверяется её доступность.

`[save].folder` — абсолютный путь или пустая строка для системной папки «Изображения\Screenshots».
Пустой хоткей отключает назначение; неизвестные поля конфига допускаются, ошибочные и повторяющиеся
комбинации отклоняются. `--warm` / `--cold` имеют приоритет над `capture.warm`.

## Что осталось

1. **M1:** закончить ручную матрицу «Недавних»: сохранение после восстановления, DPI 150/200 %, смена
   раскладки мониторов на живом экране, отказ диска. UI-проверку этой итерации пользователь остановил физическим Escape.
2. **M1:** обычное управление автозапуском из трея, завершение интерфейса и документации.
   Установщик уже включает автозапуск, переключателя в программе пока нет.
3. **M2:** аннотации, текст, размытие, выбор и изменение фигур, undo/redo, палитра.
4. **M3/M4:** закрепление снимка, перенос в чаты, окно настроек, OCR, WGC, HDR и прочее из §15.

При работе над интерфейсом сохранять ранее выбранное направление:
awesome-claude-design (editorial / Vercel grayscale) → ui-ux-pro-max → taste-skill.

## Проверено в этой итерации

- `cargo test --workspace --offline`: 46 тестов прошли на обычном рабочем столе Windows.
- Тест настоящего буфера: DIB, объявление отложенного PNG и получение PNG после рендеринга.
  Он воспроизвёл и закрыл ошибку: windows-rs принимал успешный NULL-результат
  `SetClipboardData(format, NULL)` за ошибку; теперь проверяется наличие объявленного формата.
- Нативный тест наблюдения конфига: ошибка, исправление и замена файла переименованием.
- Реальные хоткеи: окно 1247×758, монитор 1920×1080, повтор области 1247×758; ошибочный конфиг
  отклоняется, исправленный применяется без перезапуска.
- Реальные кадры двух мониторов → PNG 1920×1080. Контрольный прогон из трёх захватов:
  p50 9,3 мс, p95 13,9 мс; это короткий smoke-test, не статистический замер производительности.
- Новые проверки: восстановление кадров/выделения после повторного открытия, процесс без штатного закрытия,
  незавершённая замена state-файла, лимит 10, защита от устаревшего результата экспорта и неверных размеров PNG.
- Реальный DPAPI: round-trip и отклонение повреждённого blob. Отдельный debug-экземпляр создал зашифрованный
  снимок окна 1247×758; превью показалось в нативной ленте и успешно восстановилось в оверлей.
- `cargo clippy --workspace --all-targets -- -D warnings` проверяет исходники. Среда может отдельно сообщать
  о невозможности hard link в кэше компилятора; к замечаниям по Rust-коду это не относится.

Обычная сборка без uiAccess проверена; новая установленная сборка поверх элевированных окон ещё не проверялась.
Полная матрица DPI/HDR/RDP/нескольких GPU, сбои GPU и сохранение после отказа диска остаются открытыми.

## Сборка

```powershell
cargo test --workspace
cargo build --release
```

Для тестов нужен интерактивный рабочий стол Windows. Low-integrity sandbox запрещает захват,
глобальные хоткеи и буфер обмена. При работе в изолированной среде также используйте доступную
папку TEMP: тест наблюдателя проверяет замену уже существующего файла.

Обычная сборка: `target\release\kadr.exe`.
Для обновления установленного режима uiAccess: `cargo build --release --features uiaccess`,
затем существующий `installer\install.ps1` из PowerShell администратора. Скрипт управляет сертификатом,
доверенными хранилищами и автозапуском; проверка сборки не запускает его автоматически.

## Хранение и настройки «Недавних»

```toml
[recent]
enabled = true
max = 10
```

Выключение запрещает создавать новые черновики; прежние остаются до очистки. Сбой/отмена сохранения файла
не удаляют черновик. Завершение старого экспорта не удаляет снимок, уже открытый повторно или изменённый.

Формат v1: `%LOCALAPPDATA%\Kadr\recent\<id>\meta.toml` (только время/статус), `frames.enc`
(неизменяемый набор PNG), `state.enc` (выделение, раскладка, ревизия), `preview.enc` (PNG-превью).
Все `.enc` защищены DPAPI. Метаданные используют уже имеющийся TOML; отдельная JSON/JPEG-зависимость не нужна.
Записи заменяются атомарно через зашифрованный `.part` с `sync_all`. Незавершённая первичная запись в
`.pending-*` не показывается; подтверждённый предыдущий вариант состояния сохраняется при прерванной замене.

В debug-сборке `KADR_DEV_INSTANCE=<имя>` позволяет отдельный mutex и делает оверлеи видимыми для нативных
UI-тестов. Для изоляции теста задаются отдельные APPDATA/LOCALAPPDATA и хоткеи. Release всегда единственный
экземпляр; одновременно запускать его со старой Kadr-fixed.exe не нужно.
